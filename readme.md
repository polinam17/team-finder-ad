# TeamFinder

Платформа, где разработчики, дизайнеры и другие специалисты находят единомышленников
для pet-проектов. Реализован **вариант 1**: «Избранное» и фильтрация пользователей.

Стек: Python 3.11+, Django 5.2, PostgreSQL 16 (в Docker), Pillow.

## Инструкция для ревьюера

1. Создайте и активируйте виртуальное окружение, установите зависимости:

   ```bash
   python -m venv venv
   # Windows (PowerShell): venv\Scripts\Activate.ps1
   # Linux/Mac:            source venv/bin/activate
   pip install -r requirements.txt
   ```

2. Создайте файл `.env` из примера (значения по умолчанию подходят для проверки):

   ```bash
   cp .env_example .env        # Windows: copy .env_example .env
   ```

   В `.env` уже указан `TASK_VERSION=1` (вариант 1). Если порт 5432 на компьютере занят,
   поменяйте `POSTGRES_PORT` в `.env`, например на `5436`.

3. Запустите PostgreSQL в Docker (данные хранятся в volume `postgres_data`):

   ```bash
   docker compose up -d
   ```

4. Примените миграции и создайте тестовые данные:

   ```bash
   python manage.py migrate
   python manage.py seed_demo
   python manage.py createsuperuser      # для входа в /admin/
   ```

   `seed_demo` создаёт 4 пользователей (у каждого есть проект), участие в проектах
   и избранное. Логин `maria@yandex.ru`, пароль `password` (так же у остальных:
   `ivan@yandex.ru`, `anna@yandex.ru`, `oleg@yandex.ru`).

5. Запустите сервер: `python manage.py runserver`, откройте http://localhost:8000.

6. Тесты: `python manage.py test` (нужен запущенный PostgreSQL из шага 3).

## Что реализовано

- Регистрация, вход по email и паролю, выход, смена пароля.
- Профиль пользователя и его редактирование (аватар, о себе, телефон, GitHub).
  Телефон принимается в форматах `8XXXXXXXXXX` / `+7XXXXXXXXXX`, хранится как `+7XXXXXXXXXX`
  и уникален. Ссылка на GitHub проверяется на домен `github.com`.
- При регистрации автоматически создаётся аватарка: первая буква имени на однотонном
  светлом фоне случайного цвета.
- Проекты: список (12 на странице, новые сверху), страница проекта, создание и
  редактирование, завершение проекта, участие (`toggle-participate`).
- Вариант 1: избранное (`toggle-favorite`, страница `/projects/favorites/`) и четыре
  фильтра на странице `/users/list/`.
- Права: гости только смотрят, авторизованные управляют своими проектами,
  администратор управляет пользователями и проектами через `/admin/`.

## Отличия от рекомендаций (и почему)

- **Телефон** в модели допускает пустое значение (`null=True`, `unique=True`): при
  регистрации телефон не запрашивается, а уникальность важна только для заполненных номеров.
- **Аватар** в модели `blank=True`, но при сохранении пользователя всегда заполняется
  сгенерированной картинкой, поэтому на практике он обязательный.
- **Порядок на `/users/list/`**: от новых к старым (`-id`), как в описании страницы и
  чек-листе; в рекомендациях встречается «по id».
- В фильтрах «Авторы проектов, в которых я участвую», «Пользователи, которым нравятся
  мои проекты» и «Участники моих проектов» сам пользователь из выдачи исключён.
- URL используются со слэшем на конце (`/projects/list/`), без слэша Django делает редирект.
